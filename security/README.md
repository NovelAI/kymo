# Build trust

Run `sh security/refresh-trust.sh --rustup` before toolchain or helper downloads. It repairs the OS CA store, verifies the resulting bundle by actual DER fingerprints, and updates the calling user's Rustup. An unprivileged caller uses sudo only for OS package and certificate-store changes; Rustup remains owned by the caller.

Debian/Ubuntu deselect the affected roots through `ca-certificates.conf`. RPM-based builders persist both certificates from `blocked-roots/` in the older `blacklist` and newer `blocklist` distrust directories, even if neither root is in the current extracted bundle. They regenerate and verify before downloading packages, and again after package installation. These builders must already provide OpenSSL and `update-ca-trust`. macOS builders replace the contents of `/etc/ssl/cert.pem` with its remaining certificates; the keychain is unchanged. The script selects the verified PEM for curl, Cargo, Git, and OpenSSL clients, including Rustup's installer, and on macOS writes those choices to `GITHUB_ENV` for later Actions steps. Clients that consult native keychains or private bundles still require their own repair. Explicit caller-supplied bundles are verified before OS repair and again afterwards; an affected override fails even if it aliases the system bundle.

`verify-ca-bundle.sh --filter NEW_OUTPUT_FILE BUNDLE` prepares a clean PEM for the macOS repair. It validates every certificate and refuses malformed or empty results before publishing the output. RPM callers must ship `blocked-roots/` beside the scripts. Run `python3 security/test_trust.py` for offline regression tests using real public roots; the tests never modify the host's trust stores.

`install-dx.sh PREFIX` builds Dioxus CLI 0.7.9 from official commit `3e43ffa6cf1488d5388c888eb5f2494a006ae6de`. It verifies the source archive SHA256, applies `dx-0.7.9-tls.patch`, and installs with Cargo's `--locked` flag. The patch upgrades rustls-webpki 0.103.13 to 0.103.16 and webpki-roots 1.0.7 to 1.0.10. It also restores two missing dioxus-asset-resolver dev-dependency entries (`dioxus` and `serde_json`) so Cargo accepts the archived tree with `--locked`. This fixes the CLI's embedded trust store before it downloads build helpers; changing the application's Cargo lock or OS roots does not change a prebuilt CLI's trust store.

JavaScript actions still require patched runner images because they have their own bundled Node runtime; Python and other clients with independent trust stores retain their own prerequisites. Apple's system curl can also [fall back to native keychain trust](https://github.com/curl/curl/issues/12604), so a clean PEM alone does not qualify every macOS downloader. Both wheel workflows pass `manylinux-entrypoint.sh` to Docker for AlmaLinux manylinux_2_28 x86_64. It replaces the image's factory `SSL_CERT_FILE=/opt/_internal/certs.pem` selection with the repaired OS store; custom override paths still fail if dirty. OS trust and Rustup are repaired before Maturin's generated bootstrap script downloads build tools. A `before-script-linux` hook would run too late. The release workflows use Maturin only to build wheels, not to publish over its independent HTTPS client.

The frontend Dockerfile, internal local-runtime workflow, and exported public release workflow use this installer. They retain CLI 0.7.9 and the application's Dioxus router fork. Source compilation costs more than downloading the old executable; the frontend CI jobs allow 60 minutes. If caching this build, include the official source revision, trust patch, Rust toolchain, and target in the cache key.
